# Ева — голосовой ассистент для GNOME

Расширение GNOME Shell + фоновый демон, которые вместе дают:

- индикатор в верхней панели, меняющий цвет по состоянию (ожидание / слушаю / думаю / отвечаю);
- «динамический остров» — пилюля, всплывающая поверх верхней панели
  (в стиле iPhone Dynamic Island) с живой анимацией:
  пульсирующая волна при прослушивании, мигающие точки при обработке запроса,
  волна + краткий текст ответа при озвучке;
- постоянное прослушивание микрофона со словом-активатором **«Ева»**;
- **непрерывный диалог в стиле Алисы**: после ответа Ева продолжает слушать
  уточнения без повторного «Ева» («а завтра?», «а в рублях?», «теперь
  открой калькулятор») — каждая реплика продлевает диалог, тишина
  (~25 сек) возвращает в ожидание слова-активатора;
- распознавание речи (Vosk — для слова-активатора, faster-whisper — для самой команды);
- ответ от LLM с function calling — модель реально выполняет команды в системе,
  а не просто рассказывает, как бы она это сделала:
  - облачно через **бесплатный DeepSeek V4 Flash Free** (opencode.ai/zen,
    без ключа и регистрации) — настроен по умолчанию;
- озвучку ответа **женским голосом** — RHVoice (естественный, если установлен)
  или Piper `irina`.

Проект работает по принципу **разделения ролей** (без «гонки моделей»):
локальная Ollama выполняет действия (function calling) и рутину, а итоговый
ответ всегда формулирует и озвучивает облачная модель. Для ответов нужен
интернет; без него озвучивается текст локальной модели.

## Что умеет по голосу прямо сейчас

- открыть приложение ("Ева, открой Firefox");
- открыть картинку/видео/сайт по запросу ("покажи фото кота", "найди видео про питона");
- громкость/mute ("сделай потише", "выключи звук");
- яркость экрана ("убавь яркость до 30 процентов");
- Wi-Fi вкл/выкл;
- заблокировать экран / перевести в спящий режим;
- тёмная тема / ночной режим экрана;
- открыть ссылку в браузере;
- сказать текущее время/дату/погоду, поставить таймер, найти файл, сделать скриншот;
- курсы валют и новости ("курс доллара", "что нового в мире");
- **протокол «Утро / Старт дня»** ("Ева, доброе утро", "начни день"): открывает
  почту, календарь и таск-менеджер, зачитывает сводку (погода, курсы, новости)
  и включает фоновую музыку — см. раздел ниже;
- **протокол «Исследование / Обучение»** ("Ева, режим исследования", "давай
  учиться"): открывает браузер с вкладками (документация, Stack Overflow,
  YouTube), заметки (Obsidian/блокнот) и терминал для экспериментов —
  см. раздел ниже.

Список специально не включает выключение компьютера, перезагрузку и удаление
файлов — такие необратимые вещи лучше делать руками, а не доверять голосовому
распознаванию с шансом на ошибку. Как добавить свои команды — см. ниже.

### Быстрый роутер команд (без LLM)

Все команды из списка выше — однозначные системные действия, поэтому не
идут в LLM: `find_fast_route()` в `jarvis_daemon.py` разбирает фразу
локальными regex'ами и выполняет её напрямую (десятки миллисекунд вместо
2-15 секунд ожидания модели). Если команда роутером не распознана —
она, как и раньше, идёт в шорткаты, а затем в LLM с function calling.

Для «сложных» просьб (написать код, сайт, текст, придумать что-то) демон
не молчит, пока модель думает — сразу озвучивает короткое подтверждение
("Хорошо, начинаю работать над этим"), а затем ждёт полноценный ответ.
Сам код/большой текст вслух не зачитывается (это долго и бесполезно на
слух) — озвучивается краткая пометка, а полный ответ виден в меню
расширения (пункт с последним ответом).

## Архитектура

```
Микрофон → Vosk (слово-активатор) → faster-whisper (текст команды)
        → LLM + tools (ответить текстом или вызвать функцию):
            облачно: OpenAI-совместимый /chat/completions (см. LLM_BACKEND)
              → если функция: выполняется локально (pactl/brightnessctl/nmcli/gsettings/...)
                → результат уходит обратно в LLM → финальный текстовый ответ
        → TTS (RHVoice или Piper "irina") → колонки

Демон (Python, systemd --user) <--D-Bus (org.jarvis.Assistant)--> Расширение GNOME Shell (индикатор в панели)
```

GNOME Shell extensions не имеют доступа к микрофону и не умеют гонять тяжёлые
нейросети внутри себя — поэтому вся "тяжёлая" логика вынесена в отдельный
процесс (`jarvis_daemon.py`), а расширение — это тонкий UI-слой поверх него.

## Требования

- GNOME Shell 45–50 (проверено на 50.4)
- Python 3.10+
- LLM:
  - облачная: любой OpenAI-совместимый API (интернет) — см. «Облачная LLM»;
  - локальная: [Ollama](https://ollama.com) с лёгкой моделью `qwen2.5:3b-instruct`
    (уже скачана; модель должна поддерживать tools). Локальная модель
    выполняет действия и рутину, итоговый ответ озвучивает облако.
- Микрофон и колонки/наушники

## Проект настроен под слабое железо

Проект сознательно сконфигурирован для слабого ноутбука со встроенной
видеокартой (без дискретного GPU):

- **Простые команды выполняются без LLM вообще** (см. «Быстрый роутер команд»
  выше) — на слабом CPU это самая большая экономия времени: не тратим 2-15 с
  на ожидание модели там, где всё однозначно.
- **faster-whisper загружается лениво** — только при первой команде, а не при
  логине. В фоне демон держит лишь лёгкую Vosk-модель (~45 МБ). Выгружается
  из памяти после `WHISPER_UNLOAD_IDLE_SECONDS` простоя.
- По умолчанию стоит **`WHISPER_MODEL_SIZE = 'base'`** (int8, beam 5,
  подсказки для частых слов) — хороший баланс точности и скорости на CPU
  без GPU (~0.4-1 с на короткую команду). Если хочется ещё быстрее ценой
  точности — поставьте `tiny`; если важнее точность на шумных/длинных
  командах — `small`.
- Число потоков для распознавания (`WHISPER_CPU_THREADS`) выбирается
  **автоматически** по числу ядер CPU (`os.cpu_count() - 1`, но не больше 4) —
  одно ядро всегда остаётся системе/GNOME Shell.
- Для корректного написания частых команд используется `initial_prompt`
  (`WHISPER_INITIAL_PROMPT`) — «калькулятор» не превращается в «киркулятор».
- Демон **начинает работу с паузой** (`STARTUP_DELAY_SECONDS = 10`) — не
  конкурирует с GNOME Shell за ресурсы в момент логина.
- systemd-юнит понижает приоритет демона (`Nice=10`, `CPUWeight=20`),
  ограничивает память и стартует только **вместе с графической сессией**
  (`WantedBy=graphical-session.target`).

### Если у вас похожий на Huawei D16 ноутбук (16 ГБ ОЗУ, Intel HD Graphics)

Дополнительные советы сверх того, что уже настроено по умолчанию:

- Intel HD/UHD Graphics не ускоряет распознавание речи (нет поддержки
  CUDA/ROCm, которую использует faster-whisper) — вся нагрузка идёт на CPU.
  Весь «тяжёлый» ум переложен на облачную LLM, поэтому ноутбук почти ничего
  не считает: именно быстрый роутер команд (без LLM) даёт наибольший
  прирост отзывчивости на таком железе.
- Если ноутбук ощутимо тормозит в момент ответа ассистента — проверьте
  `htop` во время запроса: обычно это загрузка faster-whisper в момент
  распознавания команды. Можно снизить `WHISPER_MODEL_SIZE` до `base` или
  `tiny` (см. таблицу ниже).
- В `powertop`/настройках электропитания GNOME включите режим
  энергосбережения только когда ассистент не активен — во время
  распознавания/генерации ответа троттлинг CPU заметно увеличивает
  задержку.

Локальная LLM (Ollama) включена и работает в роли исполнителя действий —
см. «Облачная LLM» и «Выбор модели Ollama» ниже.

## Установка

```bash
cd jarvis-assistant
chmod +x install.sh
./install.sh
```

Скрипт:
1. ставит системные пакеты (portaudio, ffmpeg, alsa/pulse утилиты);
2. создаёт venv и ставит Python-зависимости;
3. качает маленькую Vosk-модель (~45 МБ) для слова-активатора;
4. качает женский голос Piper `ru_RU-irina-medium`;
5. копирует расширение в `~/.local/share/gnome-shell/extensions/`;
6. ставит и включает `systemd --user` сервис для демона.

### Контроль целостности скачиваемых моделей

Все файлы, которые install.sh качает при установке (Vosk-модель, голос
Piper, пакет голоса RHVoice), перед распаковкой проверяются по SHA-256
(контрольные суммы «зашиты» в скрипт). Если сумма не совпала — файл
обрыв сети/битый по другим причинам — он удаляется и скачивается заново
(до 3 попыток), после чего установка останавливается с понятной ошибкой.
Это защищает от «немого» отказа демона из-за тихо повреждённой модели.

> alphacephei.com — старый сервер, бывает, отдаёт обрыв соединения
> посреди скачивания Vosk-модели. Если install.sh упёрся в это —
> скачайте архив со стабильного соединения и распакуйте его вручную:
> `~/.local/share/jarvis-assistant/models/vosk-model-small-ru/`
> (внутри должен лежать `conf/model.conf`). install.sh увидит готовую
> модель и пропустит скачивание.

После этого:

```bash
systemctl --user start jarvis-assistant.service
```

Облачный режим (бесплатный DeepSeek V4 Flash) уже работает сразу —
никакой локальной модели не нужно.

На **Wayland** перелогиньтесь, чтобы GNOME Shell подхватил расширение.
На **X11** достаточно `Alt+F2` → `r` → `Enter`.

Дальше просто скажите **«Ева»** и, после того как индикатор в панели
позеленеет (состояние "слушаю"), задайте вопрос.

> Первая команда после установки будет медленной: faster-whisper при первом
> обращении скачает свою модель (~460 МБ для `small`) с Hugging Face в
> `~/.cache/huggingface/`. Дальше модель кэшируется, а из-за ленивой
> загрузки в фоне она не занимает память вообще.

## Проверка и отладка

```bash
# Статус демона
systemctl --user status jarvis-assistant.service

# Логи в реальном времени
journalctl --user -u jarvis-assistant.service -f

# Список аудио-устройств (если слово-активатор не ловится / не тот микрофон)
python3 -m sounddevice
```

Если слово-активатор либо не срабатывает, либо срабатывает слишком часто:

- включите отладку активации — она пишет в лог демона ВСЁ, что Vosk слышит
  во время ожидания, и видно, как модель распознаёт ваше «Ева» реально:
  ```bash
  JARVIS_WAKE_DEBUG=1 systemctl --user restart jarvis-assistant.service
  journalctl --user -u jarvis-assistant.service -f   # строки "[wake] слышу: ..."
  ```
  Распознавание идёт по фонетическому шаблону + нечёткому совпадению
  («ево», «эву», «йева», «йова», «еваа»): если Vosk пишет что-то совсем
  другое — добавьте реальные варианты в `WAKE_WORDS` (или в список
  `_WAKE_FALSE_FRIENDS`, если, наоборот, ловит чужие слова);
- отрегулируйте `SILENCE_RMS_THRESHOLD` в `backend/config.py` под уровень шума
  в комнате (проще всего — прогнать `python3 -m sounddevice` и посмотреть
  реальный входной уровень, либо добавить print(rms(...)) для отладки);
- для заметного роста точности поставьте большую Vosk-модель
  (`vosk-model-ru-0.42`, ~1.6 ГБ) и укажите её путь в `VOSK_MODEL_PATH`:
  маленькая модель (~45 МБ) — главное ограничение качества активации;
  большая держит в памяти ~1.4 ГБ постоянно, поэтому включена не по
  умолчанию.

Если расширение показывает "Демон не запущен" — значит D-Bus сервис
`org.jarvis.Assistant` не отвечает. Проверьте `journalctl` демона на ошибки
(чаще всего — не найдена Vosk/Piper модель по указанному пути, либо venv не
видит модуль `gi`).

## Если GNOME не запускается / падает после логина

Старые версии проекта (pydbus) крутили бесконечный цикл рестартов демона
сразу при логине — на слабом железе это могло валить сессию. Текущая версия
этого не делает, но если вдруг проблема вернулась, отключите всё разом:

```bash
systemctl --user disable --now jarvis-assistant.service
gnome-extensions disable jarvis-assistant@local
```

Проверьте, что именно падает:

```bash
journalctl --user -u jarvis-assistant.service -b   # логи демона
journalctl -b | grep -i gnome-shell                # ошибки оболочки
```

Демон по дизайну не может «уронить» GNOME Shell: это отдельный процесс
(systemd --user), и единственный общий ресурс — имя на D-Bus. Если падает
именно Shell — это расширение, а если после логина «выкидывает» обратно на
экран входа — смотрите раздел про ресурсы выше (пауза старта, лимиты
systemd-юнита, размер моделей).

## Настройка

Все параметры — в `backend/config.py` (секция `CONFIG`; при установке
копируется рядом с демоном):

| Параметр | За что отвечает |
|---|---|
| `WAKE_WORDS` | какие слова считать активацией |
| `WAKE_DEBUG` | писать в лог всё, что Vosk слышит при ожидании (диагностика, почему «Ева» не ловится) |
| `ACTIVATION_MODE` | стартовый режим активации: `voice` (по слову «Ева»), `hotkey` (только по горячей клавише), `both` (оба) |
| `DIALOGUE_MODE_ENABLED` | непрерывный диалог после ответа (уточнения без «Ева», как у Алисы) |
| `DIALOGUE_TIMEOUT_SECONDS` | сколько секунд тишины ждать после ответа (по умолчанию 5) — затем возврат к слову-активатору |
| `DIALOGUE_ECHO_GUARD_SECONDS` | пауза после собственной озвучки, чтобы эхо голоса не принималось за реплику |
| `DIALOGUE_MIN_SPEECH_SECONDS` | минимальная длительность живой речи для реплики (фильтрует шумы и щелчки) |
| `LLM_BACKEND` | оставлен для совместимости; роли не зависят от него: локальная Ollama выполняет действия, облако формулирует и озвучивает ответ |
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` | облачный провайдер (ключ, адрес API, модель) |
| `SYSTEM_PROMPT` | характер и стиль ответов ассистента |
| `PIPER_VOICE_MODEL` | путь к голосу Piper (женский `irina` по умолчанию) |
| `RHVOICE_VOICE` | женский голос RHVoice (`Elena` / `Irina`), если RHVoice установлен |
| `WHISPER_MODEL_SIZE` | точность/скорость распознавания команды (`small` — точнее всего, `base`/`tiny` — быстрее) |
| `WHISPER_CPU_THREADS` | сколько ядер отдавать распознаванию (меньше = меньше лагов системы) |
| `WHISPER_BEAM_SIZE` | больше — точнее, но медленнее (по умолчанию 5) |
| `WHISPER_INITIAL_PROMPT` | подсказка с частыми словами — правильное написание |
| `WHISPER_LAZY_LOAD` | грузить whisper только при первом запросе (`True` экономит RAM/CPU в фоне) |
| `STARTUP_DELAY_SECONDS` | пауза после логина перед загрузкой моделей |
| `SILENCE_RMS_THRESHOLD`, `SILENCE_HANG_SECONDS` | когда считать, что пользователь договорил |
| `MIC_DEVICE` | индекс конкретного микрофона, если устройство по умолчанию не то |

Приватные значения (API-ключи, секрет прокси) можно не вписывать в файл:
они читаются из переменных окружения или из `~/.config/jarvis-assistant/config`
(формат `ИМЯ=значение`, по одному на строку). Приоритет: переменная окружения
> файл конфига > значение в `config.py`. Секрет прокси для Telegram
(`TG_WSPROXY_SECRET`) при отсутствии всех источников генерируется один раз
и сохраняется в `~/.local/share/jarvis-assistant/tg-ws-proxy.secret` (права 600).

После изменений — `systemctl --user restart jarvis-assistant.service`.

### Режим активации: голос или горячая клавиша

Ассистент умеет активироваться двумя способами — настраивается в расширении
(иконка в панели → пункты выше) либо прямо в конфиге `ACTIVATION_MODE`:

- **voice** (по умолчанию) — постоянно слушает микрофон, реагирует на слово
  «Ева». Удобно, но микрофон занят постоянно;
- **hotkey** — микрофон не слушается; активация только по горячей клавише
  (или пункту «Активировать вручную» в меню расширения). Экономнее и
  приватнее;
- **both** — и по голосу, и по клавише.

Горячая клавиша по умолчанию — **Ctrl+Shift+Пробел**, меняется в
«Настройки GNOME → Клавиатура → Настраиваемые сочетания клавиш»
(раздел расширения Jarvis). При выборе режима через расширение демону
сообщается новый режим на лету, без перезапуска.

Во время обработки запроса/озвучки повторное слово «Ева» прерывает текущий
запрос, и Ева сразу слушает новую команду (в режиме `hotkey` прерывание
голосом отключено).

### Непрерывный диалог (как у Алисы)

«Ева, какой курс доллара» → «а в евро?» → «а теперь открой калькулятор» —
второе слово-активатор больше не нужно. После ответа Ева переходит в
состояние «Диалог» (индикатор синеет) и слушает следующую реплику без «Ева»:

- окно диалога короткое — `DIALOGUE_TIMEOUT_SECONDS` (по умолчанию 5 с):
  успеть задать уточнение, но не слышать фоновый разговор/телевизор
  по полминуты; каждая реплика продлевает диалог, контекст сохраняется;
- репликой считается только «живая» речь длительностью
  `DIALOGUE_MIN_SPEECH_SECONDS` (0.6 с): щелчки, кашель и короткие шумы
  команду не запускают;
- если услышанное не разобралось (шум, телевизор) — Ева молча завершает
  диалог, без голосового «Не расслышал»;
- тишина `DIALOGUE_TIMEOUT_SECONDS` возвращает в обычное ожидание «Ева»;
- одно «Ева» без продолжения тихо завершает диалог;
- в режиме `hotkey` диалог не включается (микрофон не слушается).

Отключается настройкой `DIALOGUE_MODE_ENABLED = False`.

### Голос (женский)

По умолчанию стоит женский голос. Два варианта:

1. **RHVoice** — заметно естественнее, работает офлайн:
   ```bash
   sudo pacman -S rhvoice rhvoice-language-russian rhvoice-voice-elena   # Arch / CachyOS
   sudo apt install rhvoice rhvoice-language-russian rhvoice-voices      # Debian / Ubuntu
   systemctl --user restart jarvis-assistant.service
   ```
   Голоса в официальных репозиториях — отдельные пакеты `rhvoice-voice-*`
   (elena, irina, anna, tatiana, ...). Без прав администратора install.sh
   распакует голос `elena` в `~/.local/share/jarvis-assistant/models/rhvoice/`
   — демон найдёт его сам. Поменять голос можно через `RHVOICE_VOICE`.
2. **Piper** — резервный вариант без установки чего-либо (голос `irina`,
   женский). Другие русские голоса Piper: `denis`, `dmitri`, `ruslan` —
   скачайте `.onnx`/`.onnx.json` в `~/.local/share/jarvis-assistant/models/piper/`
   и поправьте `PIPER_VOICE_MODEL`.

### Облачная LLM и локальная Ollama (разделение ролей)

Демон работает без «гонки»: **локальная Ollama выполняет**, **облако
озвучивает**. На каждый запрос локальная модель первой вызывает нужные
инструменты (function calling) и возвращает результат, затем облако
формулирует итоговый ответ, который и читается вслух. Локальная модель
вслух не отвечает — её текст используется только как запасной вариант:
после серии 429/сбоев облако на минуту отключается, и Ева озвучивает
то, что успела выполнить/сказать локальная модель.

**Облачный вариант уже настроен по умолчанию** — DeepSeek V4 Flash Free
через бесплатный шлюз opencode.ai/zen (никаких ключей и регистраций не
нужно). В `backend/config.py` это выглядит так:

```python
LLM_BACKEND = 'openai'
OPENAI_BASE_URL = 'https://opencode.ai/zen/v1'
OPENAI_MODEL = 'deepseek-v4-flash-free'
```

Локальная модель поддерживает function calling — все голосовые команды
(«Ева, открой браузер») выполняются локально даже при перебоях интернета
(озвучка тогда идёт текстом локальной модели).

**Платные альтернативы** — замените три строки выше на любого провайдера
(API-ключ задаётся переменной `OPENAI_API_KEY` или прямо в конфиге):

| Провайдер | BASE_URL | Модель (пример) | Примечания |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | самый простой |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini`, `deepseek/deepseek-chat` | много моделей, есть бесплатные |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.1-8b-instant` | очень быстро, бесплатный тариф есть |

### Выбор модели Ollama (локальный исполнитель)

По умолчанию стоит **`qwen2.5:3b-instruct`** (уже скачана, ~2 ГБ) —
лучший баланс для слабого ноутбука: отвечает за 2-5 с и занимает ~2 ГБ ОЗУ.
Если хочется совсем лёгкую нагрузку в ущерб качеству — `ollama pull qwen2.5:1.5b-instruct`;
при достаточном железе можно вернуть `qwen2.5:7b-instruct` (4.7 ГБ, медленнее на CPU).

Модель должна поддерживать tools (function calling) — у qwen2.5 это есть.

### Протокол «Утро / Старт дня»

Фразы «доброе утро», «начни день», «старт дня», «утренняя сводка» и
«план на день» запускают утренний протокол (`action_morning_routine`):

1. открывает почту, календарь и таск-менеджер — сначала установленное
   приложение (если есть), иначе веб-версию по ссылке;
2. зачитывает сводку: сегодняшняя дата, погода, курсы валют
   (доллар/евро/юань — open.er-api.com) и первые заголовки новостей
   (Lenta.ru/РИА Новости, бесплатный RSS);
3. включает фоновую музыку/подкаст (приложение или веб-плеер) на
   громкости ~40%, чтобы не мешала речи.

Всё настраивается в секции `ПРОТОКОЛ «УТРО / СТАРТ ДНЯ»` конфига:
`MORNING_APPS` (список `{'app': 'почта', 'url': 'https://mail.google.com'}` —
app = установленный клиент, url = веб-версия, если клиента нет),
`MORNING_MUSIC_APP` / `MORNING_MUSIC_URL` / `MORNING_MUSIC_VOLUME`,
`NEWS_HEADLINES`, `RATES_CURRENCIES`. Координаты города для погоды —
`WEATHER_LAT`/`WEATHER_LON`.

Похожие вопросы («курс доллара», «что нового в мире») тоже обрабатываются
мгновенно (`get_rates`, `get_news`).

### Протокол «Исследование / Обучение»

Фразы «режим исследования», «исследование», «давай учиться», «учиться»,
«хочу позаниматься» запускают протокол исследования
(`action_learning_routine`):

1. открывает браузер с вкладками: документация (MDN), Stack Overflow, YouTube;
2. открывает заметки — первое установленное приложение из `LEARNING_NOTES_APPS`
   (по умолчанию Obsidian, затем текстовый редактор), если ни одного нет —
   веб-версию;
3. открывает терминал для экспериментов.

Настройка — секция `ПРОТОКОЛ «ИССЛЕДОВАНИЕ / ОБУЧЕНИЕ»` конфига:
`LEARNING_TABS` (список URL вкладок) и `LEARNING_NOTES_APPS` (список
`{'app': 'obsidian', 'url': ''}`).

## Как добавить свою команду управления системой

В `jarvis_daemon.py`, секция `SYSTEM ACTIONS`:

1. Напишите функцию `def action_my_thing(args): ...`, которая выполняет
   нужное (обычно через `subprocess`/`gsettings`/`gdbus`) и возвращает
   короткую строку-результат.
2. Добавьте её в словарь `ACTIONS['my_thing'] = action_my_thing`.
3. Опишите её для модели в списке `TOOLS` (имя, описание, параметры —
   формат как у остальных функций, это стандартный JSON Schema).
4. Перезапустите демон.

LLM сама решит, когда вызывать функцию, по описанию — писать отдельный
парсер команд не нужно. Этого достаточно, чтобы команда заработала (но
через LLM — то есть с задержкой в несколько секунд).

### Как сделать команду мгновенной (без LLM)

Если команда однозначная (например, всегда один и тот же жёсткий шаблон
фразы, без свободной формулировки) — добавьте её ещё и в **быстрый роутер**,
секция `FAST INTENT ROUTER` перед секцией шорткатов:

```python
@_route(r'^включи\s+режим\s+полёта$')
def _r_airplane_mode(m):
    return action_airplane_mode({})
```

Порядок объявления важен: более специфичные (узкие) паттерны должны идти
раньше более широких, иначе широкий перехватит фразу первым. Если сомневаетесь,
что паттерн однозначен — не добавляйте его в роутер, пусть остаётся только
в `TOOLS` и решается через LLM (это безопаснее, просто немного медленнее).

## Безопасность и ограничения

- **Function calling — это исполнение того, что решит LLM.** Список функций
  специально ограничен обратимыми действиями (громкость, яркость, Wi-Fi,
  тема, блокировка/сон, запуск приложений, открытие ссылок). Выключение
  компьютера, перезагрузка, удаление/изменение файлов сознательно не
  реализованы — при желании добавляйте их только если осознаёте риск
  случайного срабатывания из-за ошибки распознавания речи.
- Если хотите вообще отключить управление системой и оставить только
  разговорного ассистента — поставьте `ALLOW_SYSTEM_ACTIONS = False`
  в конфиге.
- `open_app` ищет приложение по подстроке названия среди установленных
  `.desktop`-файлов — при неоднозначных названиях может открыть не то,
  что ожидалось; в этом случае просто уточните название точнее.
- Точность слова-активатора зависит от микрофона и шума в комнате — маленькая
  Vosk-модель компактна, но не идеальна. Если это станет проблемой, можно
  заменить wake-word детектор на openWakeWord с моделью "hey_jarvis".
- Демон слушает микрофон непрерывно, пока запущен — это ожидаемо для
  голосового ассистента с активацией по слову, но учитывайте это с точки
  зрения приватности.
- Ответы генерирует **облачная** модель: текст запроса и ответа уходят в
  облачный API (по умолчанию — бесплатный шлюз opencode.ai/zen). Если
  приватность важнее — смените провайдера или отключите ассистента.
